# v1.2 domain-correctness implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a single, defensible public PD and IFRS 9 mechanics demonstration with a collectable model contract, correct ECL maths and verified deployment.

**Architecture:** Replace the application profile with a 15-field `public_demo` profile. Train and version that model plus a same-profile logistic challenger. Route every ECL report through the survival-weighted scenario core, and make the API/dashboard consume only the persisted public-demo contract.

**Tech Stack:** Python 3.12, pandas, scikit-learn, LightGBM, SHAP, FastAPI, Streamlit, pytest, Ruff, Docker and GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-26-v1.2-domain-correctness-design.md`

## Global constraints

- Keep Home Credit data out of Git; version only fitted artefacts and metadata.
- Use dataset monetary units in every public API, dashboard and report surface.
- Do not use a protected attribute in the served model or public request schema.
- Test each new behaviour before its production implementation.
- Do not fit a calibration model or choose a threshold on the untouched test fold.
- Do not claim an IFRS 9 accounting provision; call the result a mechanics demonstration.
